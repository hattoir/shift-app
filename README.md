# シフト管理アプリ

一日2枠(🌅早番・🌙遅番)のシフトを管理するWebアプリです。

## 機能

- **シフト表** (`/`) — 誰でも閲覧できる月間シフトカレンダー。「🔄 更新」ボタンで最新を取得
- **希望日入力** (`/availability`) — メンバーが名前を選び、日付をタップして希望を入力
  - ○ どちらでもOK / 早 早番だけ / 遅 遅番だけ / **✕ この日は入れない**
  - 「まとめて入力」で月ぜんぶ・週ごとの一括指定もできます
- **管理者ページ** (`/admin`) — パスワードでログインして:
  - メンバーの追加・削除
  - 固定ルール(曜日ごと)…「この曜日はこの人を入れる」と「この曜日は入れない」の2種類
  - 🪄 自動割当(対象月を明記して実行。結果の内訳も確認できます)
  - **日付をタップして、その日の担当を変更するダイアログ**(スマホ対応)
- **接続診断** (`/health`) — 環境変数・DB接続・SQLの実行状況を確認できます

---

## ⚠️ 既存アプリを更新する人へ: Supabaseで実行が必要なSQL

「入れない日」と「曜日ごとの除外ルール」を使うために、**1回だけ**SQLの実行が必要です。
既存のデータは消えません(`alter table` のみで、`drop table` はしていません)。

1. Supabase を開く → 左メニューの **SQL Editor**
2. `supabase/migrations/001_add_off_and_rule_kind.sql` の中身をすべて貼り付ける
3. **Run** を押す

実行できたかどうかは `/health` ページの「接続テスト」欄で確認できます
(「追加SQL (migrations/001)」が **OK 実行済み** になっていればOK)。

実行前に「✕ 入れない」を保存しようとすると、その旨のエラーメッセージが出ます。

> はじめて作る場合は、この手順は不要です。`supabase/schema.sql` に最新の内容が入っています。

## セットアップ手順

### 1. Supabase(データベース)

1. https://supabase.com で無料アカウントを作り「New project」
2. 左メニューの **SQL Editor** を開き、`supabase/schema.sql` の中身を貼り付けて **Run**
3. **Project Settings → API** で以下をメモ:
   - `Project URL`(例: https://xxxx.supabase.co)
   - `service_role` キー(secret の方。anon ではない)

### 2. ローカルで動かす(任意)

```bash
npm install
```

```bash
npm run dev
```

`.env.local.example` を `.env.local` にコピーして、SupabaseのURL・キー・管理者パスワードを記入してください。
http://localhost:3000 で確認できます。

### 3. Vercel にデプロイ

1. このフォルダを GitHub リポジトリにpush
2. https://vercel.com にGitHubでログイン → **Add New → Project** → リポジトリを選択
3. **Environment Variables** に以下の3つを設定:

   | Name | Value |
   |------|-------|
   | `SUPABASE_URL` | SupabaseのProject URL |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_roleキー |
   | `ADMIN_PASSWORD` | 管理者用パスワード(自分で決める) |

4. **Deploy** を押す → 発行されたURLをメンバーに共有

## 使い方の流れ

1. 管理者が `/admin` でメンバーを登録、必要なら固定ルールを設定
2. メンバーに URL を共有 → 各自 `/availability` で来月の希望を入力(入れない日は ✕)
3. 管理者が「🪄 自動割当」→ カレンダーの日付をタップして手動で調整
4. みんなが `/` でシフトを確認

### 自動割当の優先順位

上から順に判定します。

1. **🔒 手動で固定した枠** … 絶対に変更しません
2. **その日「✕ 入れない」の人 / その曜日が「入れない」ルールの人** … 固定ルールがあっても絶対に割り当てません
3. **固定ルール(この曜日はこの人)** … 優先的に割り当てます
4. **希望日** … その月の割当回数が少ない人から順に(公平になるように)
5. 同じ人が同じ日の早番と遅番を兼任することはありません

割当のあと「自動割当のくわしい結果を見る」を開くと、対象の月・割り当てた枠数・埋まらなかった枠とその理由が確認できます。

### 日付をタップして手動で変更する

管理者ページ「シフト作成」タブで日付をタップすると、その日の編集ダイアログが開きます。

- 早番・遅番それぞれで、メンバーのボタンをタップして担当を決めます
- ボタンにはその日の状況が出ます(`○ 空きあり` / `早のみ` / `遅のみ` / `固定` / `✕ 入れない` / `希望なし`)
- もう一方の枠に選んだ人はグレーになり、同じ日の兼任はできません
- 「未定に戻す(クリア)」で空にできます
- 「🔒 固定中」にすると、自動割当で上書きされなくなります
  (担当者なしのまま🔒にすると「この枠は空のまま」を固定できます)
- 「保存する」を押すとカレンダーがすぐ更新されます

## 更新内容(このバージョンでやったこと)

### 1. 手動でシフトを変更するUI
- カレンダーのセル内の `<select>` を廃止し、**日付タップで開く編集ダイアログ**に変更
- メンバーは大きなボタン(タップ領域44px以上)で選択。その日の希望状況をラベル表示
- 同一日の早番・遅番の兼任を、画面(グレーアウト)とAPIの両方で禁止
- `🔒 固定`のON/OFFをダイアログから切り替え可能に

### 2. 表示が更新されない問題
調べた結果、**月の扱い(`lib/month.js` の `monthRange` / 管理画面の表示月)にはズレはありませんでした**。
残っていた原因になりうる箇所を次のように直しています。

- APIのレスポンスに `Cache-Control: no-store` 等を明示(`lib/res.js` を新設し全APIで使用)。
  Vercel/CDN/ブラウザに古い内容が残らないようにしました
- 全APIルートに `export const revalidate = 0` を追加(`dynamic = 'force-dynamic'` はもともと設定済み)
- クライアントの `fetch` にキャッシュ回避用のパラメータを追加(`lib/api.js`)
- **シフト表・管理画面に「🔄 更新」ボタンを追加**。最終更新時刻も表示
- シフト表は、別タブから戻ってきたときに自動で取り直すようにしました
- 自動割当の完了メッセージに対象月を明記(例: `2026年9月に14枠を割り当てました`)
- 0枠のときは理由が分かる文言を表示
- 実行前に確認ダイアログを表示
- 自動割当の結果(対象月・枠数・埋まらなかった枠と理由)を管理画面で折りたたみ表示

### 3. 「入れない日」と除外ルール
- `availability.slot` に `'off'` を追加(SQLは `supabase/migrations/001_add_off_and_rule_kind.sql`)
- `fixed_rules.kind`(`'assign'` / `'off'`)を追加し、「この曜日は入れない」を設定可能に
- 希望日入力のタップ循環を `なし → ○ → 早 → 遅 → ✕ → なし` に変更、色分けと凡例も更新
- 「まとめて入力」(月ぜんぶ / 週ごと)を追加
- 自動割当の優先順位を上記のとおり実装
- 固定ルール一覧を曜日ごとにグループ化
